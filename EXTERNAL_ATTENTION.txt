TMX — External attention and account configuration
=================================================
Items in this file cannot be completed in application code alone. They need
an outside vendor account, DNS, bank setup, or a legal/ops decision.
Until each item is connected, TMX shows a Coming soon placeholder and
disables send/execute actions instead of faking success. DocHub send and
Stripe invoice pay are on when Supabase is configured (see sections 2
and 3). Talent and brand portals never mention this file.

Last updated: 2026-10-07
Product owner: Nzinga MGMT / Talent Manager X

----------------------------------------------------------------------
1. Twilio (voice + SMS) — REPLACES RingCentral
----------------------------------------------------------------------
Why it blocks: Text Messaging Center, click-to-call, inbound SMS badge,
call recordings, and automated SMS (72-hour contract notice, payday,
call-sheet updates) cannot send or receive until Twilio is live.

Who: Director / IT
What to do:
  - Create a Twilio account (twilio.com) under the agency entity.
  - Buy at least one US local or toll-free number with Voice + SMS + MMS.
  - Copy Account SID and Auth Token into Supabase Edge Function secrets:
      TWILIO_ACCOUNT_SID
      TWILIO_AUTH_TOKEN
      TWILIO_FROM_NUMBER
  - Point inbound SMS webhook to:
      https://<project>.supabase.co/functions/v1/twilio-webhook
  - Point voice status / recording callbacks to the same function
    (or twilio-voice when split).
  - Enable Twilio recording storage if call recordings should appear
    on talent History.
  - Remove RingCentral app credentials from Settings and Edge Function
    secrets after cutover (RINGCENTRAL_*).

Blocked product: /messaging, header SMS badge, TalentRecord click-to-call.

2. DocHub (exclusive e-sign)
----------------------------------------------------------------------
The app calls https://dochub.com/api/v2 with DOCHUB_API_KEY (header
X-API-Token). dochub-webhook verifies X-DocHub-Signature-256
(HMAC-SHA256 of timestamp + "." + raw body, prefix dochub_v1=).

Send paths:
  - Publish contract (PDF or image on the talent record)
  - Create & Send on a renewal preview (HTML)
  - Brands → Send usage agreement (HTML)
Each request expires in 3 days (DocHub's expiry unit is whole days;
72 hours is sent as 3). The signer annotates in DocHub (canFreeEdit)
because this flow does not pre-place signature fields.

Webhook URL:
  https://rvuchforbheotenhkxnm.supabase.co/functions/v1/dochub-webhook
Subscribe to: sign_request.created, signer.finalized, signer.rejected,
sign_request.voided, document.status_changed.
document.status_changed is the terminal event (completed, expired,
voided, rejected). DocHub does not emit document.sent / document.signed.

Open in DocHub uses the document fullUrl (https://dochub.com/d/{id}).
Demo mode (no Supabase) still shows Coming soon and does not send.

3. Stripe — brand invoice checkout
----------------------------------------------------------------------
Pay Invoice on /client/billing opens Stripe Checkout (card and ACH)
for the invoice total stored in client_invoices. stripe-webhook marks
the invoice paid only on payment_intent.succeeded, invoice.paid, or
checkout.session.async_payment_succeeded. ACH stays "processing" until
the bank settles. A failed charge does not mark the invoice paid.

Secrets (Supabase Edge Functions, not Vite):
  STRIPE_SECRET_KEY
  STRIPE_PUBLISHABLE_KEY
  STRIPE_WEBHOOK_SECRET

Webhook URL (JWT verification off):
  https://rvuchforbheotenhkxnm.supabase.co/functions/v1/stripe-webhook
Events: payment_intent.succeeded, payment_intent.processing,
payment_intent.payment_failed, checkout.session.completed,
checkout.session.async_payment_succeeded,
checkout.session.async_payment_failed, invoice.paid, charge.failed.

Payout bank is still a Stripe dashboard setting: Chase escrow holding
account, not the operating account. ACH Direct Debit must be enabled
on the Stripe account or checkout creation returns Stripe's error.

6. Background screening provider (Checkr / Certn / DISA)
----------------------------------------------------------------------
Why it blocks: Scout "Initiate Screening" and Client Packet submit
(screening required). TMX is provider-agnostic; pick ONE first.

Who: Director / Success Manager (compliance)
What to do:
  - Choose provider (Checkr recommended as first adapter).
  - Create account, get API keys, candidate-invite flow, webhook.
  - Store:
      SCREENING_PROVIDER     (checkr | certn | disa)
      SCREENING_API_KEY
      SCREENING_WEBHOOK_SECRET
  - Map provider statuses into TMX:
      Not Started, Invitation Sent, Awaiting Applicant,
      Screening in Progress, Screening Complete, Review Required,
      Cleared, Disputed, Unable to Complete
  - Restrict full report bodies to authorized roles; scouts see
    status only unless granted report access.

Blocked product: Screening Workspace Initiate Screening; packet submit
until screening is Cleared or Review Required is resolved.
